# Phase 1 Report

## Status

PASS

Hidden state is now separated at schema, service, Streamlit session, export, role access, logging and Patient Agent prompt boundaries. Default learner mode cannot receive or render the full chest-pain case before disclosure. Instructor access requires `APP_ROLE=instructor` and is checked again in the service layer.

## Goals

- Establish `FullPatientCase`, `LearnerVisibleCase`, `InstructorCaseView` and `UnlockedEvidence` models.
- Remove full-profile display and storage from learner Streamlit state.
- Add explicit deployment-level instructor mode.
- Keep hidden state out of learner responses, exports, browser fields and ordinary logs.
- Add security tests for role separation, reset isolation and disclosure behavior.
- Preserve all existing cases and disclosure benchmark results.

## Known Issues

- `APP_ROLE` is a deployment-wide switch, not login-based teacher authorization.
- The full case remains in server-side SQLite by design; filesystem/database access must be protected operationally.
- Instructor `learner_action_trace` is currently derived from consultation rows and cannot include clinical tool actions that do not yet exist.
- Unlock persistence is still a case-level boolean with per-turn snapshots, not a dedicated item-level `UnlockedEvidence` table.
- External provider behavior beyond the deterministic prompt/data gate is not clinically validated.
- OSCE scoring accuracy limitations from Phase 0 remain unchanged.

## Risks

- Starting a public learner deployment with `APP_ROLE=instructor` would deliberately expose the instructor tab; deployment configuration must be controlled.
- Future developers could bypass `app/streamlit_services.py` and call internal `SimuEngine.generate_patient*()` directly from UI code; security tests and code review must preserve the facade boundary.
- A future generic metadata field on the learner schema could weaken the allowlist. Keep `extra="forbid"` and explicit fields.
- Phase 2 schema changes must not place unreleased test results inside `UnlockedEvidence` before a successful tool action.
- The deterministic disclosure matcher is authored and English-focused; multilingual semantic coverage remains a later evaluation task.
