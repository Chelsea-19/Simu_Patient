# Phase 3 Report

## Status

PASS

The chest-pain Demo now has an explainable, deterministic safety branch. An unsafe home plan is
blocked before assessment, the reason is written to Action Trace without revealing the answer, and
the learner can correct the missing action and resubmit. Reasonable urgent plans can complete even
when non-blocking history gaps remain for formative feedback.

## Goals

- Add case-configured chest-pain safety checks.
- Block only safety-critical combinations rather than every omission.
- Keep feedback reflective and free of ground-truth diagnosis disclosure.
- Persist each safety decision and its evidence in Action Trace.
- Prevent learner Prompt Injection from revealing state, rewriting tool facts, changing scores,
  disabling blocking, or switching the patient role.
- Preserve the Phase 1 disclosure boundary and Phase 2 offline task workflow.

## Known Issues

- Safety matching is case-authored keyword logic, not semantic clinical validation. The Phase 3
  chest-pain vocabulary is primarily English; equivalent Chinese clinical phrasing needs authored
  aliases before a bilingual competition flow.
- The blocking rule is intentionally narrow. A high-risk non-home plan may pass with missing ECG if
  urgent escalation is explicit; the omission remains visible for formative feedback.
- Only `chest_pain_001` has a Phase 3 safety configuration. Other cases fail open to completion with
  an explicit “no case-specific blocking rule” review.
- Prompt-pattern interception is defense in depth for known control attempts, not proof against all
  future jailbreak wording.
- The existing hybrid formative assessment still uses LLM qualitative extraction behind a system
  boundary. Phase 3 removes known control instructions, clamps output to the schema/score range, and
  keeps safety blocking deterministic, but the broader assessment design still requires later
  evidence-based scoring work.
- The safety-rule configuration requires instructor clinical review; schema validity does not prove
  medical correctness.

## Risks

- Expanding keyword lists without tests could create false positives, especially for negated plan
  language such as “do not discharge”.
- New cases without `safety_supervision` do not receive a hard block.
- LLM providers can vary in natural-language quality, although hidden facts, tools, workflow,
  blocking, transcript sanitization, and score persistence remain outside learner control.
- Safety-event exports contain learner actions and legitimately unlocked evidence and must continue
  using the Phase 1 role boundary.
- This implementation must be presented as formative training supervision, not a real-world triage
  or treatment guarantee.
