# Phase 2 Report

## Status

PASS

The chest-pain Demo now runs as a persistent clinical task rather than chat plus scoring. A learner can take history, request YAML-backed vital signs, perform configured examinations, order ECG and laboratory tests, submit a differential diagnosis and management plan, finish the encounter, receive formative assessment, resume the session, and review an append-only Action Trace. The complete core path runs with MockProvider and no network/API access.

## Goals

- Define and persist the required Encounter State.
- Implement the staged clinical training state machine with reasonable revisits.
- Provide deterministic clinical tool interfaces and structured results.
- Move all chest-pain examination/investigation facts into YAML.
- Record every successful, duplicate and rejected action in Action Trace.
- Add a Streamlit clinical investigation workbench.
- Preserve Phase 1 hidden-state isolation and existing benchmark behavior.

## Known Issues

- Phase 2 validates workflow completeness but does not yet judge whether a management plan is clinically safe. A learner can submit a non-empty unsafe plan; deterministic safety blocking belongs to Phase 3.
- `safety_flags`, `safety_event` and score-event fields exist and are traced, but clinical safety rules are not populated yet.
- The existing formative assessment mainly scores chat transcript content; it does not yet score tool selection, differential quality or management safety from Action Trace.
- Only `chest_pain_001` has configured clinical tools. Other cases remain valid and return safe “not configured” responses.
- Simulated `elapsed_time` represents authored task minutes, not wall-clock duration.
- Resume-by-session-ID is a Demo recovery mechanism, not authenticated learner ownership.
- State is persisted as a validated JSON snapshot; schema migrations/versioning will be needed if deployed beyond the competition prototype.
- Append-only behavior is enforced by repository API and tests, not by database triggers.
- Hints are generic stage-aware scaffolds. Personalized three-level coaching is planned for the later learning/remediation phase.

## Risks

- Phase 3 must prevent an apparently complete but unsafe discharge plan from reaching assessment.
- Tool configuration authors could enter clinically incorrect facts; instructor YAML validation and case review remain necessary.
- Unknown `unlock_condition` strings fail closed, but authoring feedback for invalid semantic values should be strengthened.
- The current state machine is single-learner/single-process friendly; concurrent edits to the same session do not yet use optimistic locking.
- SQLite is appropriate for the offline Demo but Streamlit Community Cloud can reset local storage when the app sleeps.
- The Action Trace contains learner inputs and legitimately unlocked clinical evidence; exports and teacher access must continue respecting Phase 1 role boundaries.
